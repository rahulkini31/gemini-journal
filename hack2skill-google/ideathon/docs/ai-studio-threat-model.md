# AI Studio Threat Model

> Status: approved by independent human gate audit on 2026-08-26; baseline coding gate opened.

| Zone | Concrete Asset/Data Flow | Realistic Threat | Impact | Required Countermeasure | Verification Test | Bounded Residual Risk |
|---|---|---|---|---|---|---|
| Zone 1: Input surfaces | Request payload size on HTTP ingestion endpoint | Malicious attacker sends an oversized HTTP request body (exceeding 4 KiB) to exhaust server memory and cause denial of service | Server resource exhaustion, crash, and service unavailability for valid users | Enforce top-level request body parsing middleware before all route handlers with strict payload size limit returning HTTP 413 for bodies exceeding 4 KiB | Send 5 KiB payload to endpoint and confirm immediate HTTP 413 response without parsing or processing downstream | Bounded residual risk of single-request connection overhead managed by Cloud Run automated instance scaling and rate limiting |
| Zone 1: Input surfaces | Incoming HTTP request body JSON payload | Client submits malformed or unparseable JSON structures to trigger unhandled server exceptions | Runtime crash, unhandled 500 exceptions, stack trace leakage, and endpoint instability | Mount defensively configured JSON body parser prior to all routes; catch syntax errors and reject missing or invalid JSON with HTTP 400 Bad Request | Send syntactically invalid JSON payload and verify server returns clean HTTP 400 Bad Request without application crash | Bounded residual risk of bad request processing overhead mitigated by early middleware termination and monitoring |
| Zone 1: Input surfaces | Journal text input payload in HTTP request body | Attacker submits malformed string types, non-string objects, executable HTML/script payloads, or invalid schemas in journal entries | Application instability, schema corruption, client-side script execution, or unexpected backend processing | Treat journal text input as explicitly untrusted HTTP input; enforce strict string type and schema validation prior to processing in addition to separate token cap and 4 KiB payload boundaries | Submit non-string types, malformed objects, and XSS script tags in journal text field; verify backend rejects invalid schemas/types with HTTP 400 and encodes script tags without execution | Bounded residual risk of invalid payload parsing overhead managed by early validation middleware termination |
| Zone 1: Input surfaces | Firebase ID Token in HTTP Authorization Header | Unauthenticated or malicious attacker submits fake, missing, expired, wrong issuer/audience, or revoked bearer token in HTTP Authorization header | Unauthorized access to API endpoints and unauthorized invocation of Gemini backend resources | Validate Firebase ID Token on every request via Firebase Admin SDK, explicitly checking signature, issuer equal to project issuer URL, audience equal to this project ID, expiration, and revoked-token status; reject non-compliant or revoked tokens immediately with HTTP 401 | Submit requests with missing, forged, expired, wrong issuer/audience, and revoked JWTs and verify server rejects all attempts with HTTP 401 Unauthorized | Bounded residual risk of cryptographic token verification CPU cycles bounded by rate limiting and identity provider degradation protocols |
| Zone 1: Input surfaces | Firebase App Check token in HTTP header | Malicious actor bypassing front-end client calling endpoints directly without valid attestation token | Unauthorized API usage by non-app clients leading to quota depletion | Verify Firebase App Check token before every model call using dedicated runtime identity; return HTTP 401 if attestation fails | Send valid Firebase Auth token with missing or fake App Check token and verify request fails with HTTP 401 | Bounded residual risk of attestation service unavailability degrading non-attested client access until attestation backend recovers |
| Zone 1: Input surfaces | Client-supplied User ID parameter in body or URL | Malicious authenticated user passes another user's UID in payload to read or overwrite foreign data | Horizontal privilege escalation and unauthorized access to another user's journal entries | Backend ignores client-provided UID fields entirely and derives all database paths strictly from the verified Firebase Auth UID token | Submit valid token for User A while placing User B UID in request payload; verify operation affects only User A path | Bounded residual risk of broken authorization mitigated by central token context binding and strict schema validation |
| Zone 1: Input surfaces | Client-supplied Interaction ID parameter | Malicious user passes malformed or cross-user interaction IDs in path parameters to manipulate document lookups | Unauthorized state overwrite or invalid Firestore document path errors | Sanitize client interaction IDs against strict alphanumeric schema and restrict Firestore path targeting to verified UID namespace | Submit path manipulation strings such as dot-dot-slash in interaction ID and verify rejection with HTTP 400 | Bounded residual risk of invalid parameter logging overhead controlled by structural log sanitization |
| Zone 2: Planning and reasoning | User journal text input to Gemini model prompt | Direct prompt injection attack embedding malicious prompt instructions inside journal entries to hijack system behavior | Loss of system instruction integrity, model output manipulation, or unauthorized prompt behavior | Strict instruction and data separation using explicit system instruction delimiters; isolate untrusted user text inside data roles | Inject malicious instructions such as ignore previous instructions into journal entry and verify system context remains unchanged | Bounded residual risk of dynamic model misinterpretation mitigated by strict zero-tool environment and prompt boundary validation |
| Zone 2: Planning and reasoning | Untrusted stored journal history retrieved from Firestore | Indirect prompt injection embedded in past journal entries attempting to alter reasoning in multi-turn history | Escalation of prompt injection across multi-turn context leading to degraded model outputs | Wrap all retrieved prior journal text in strict data blocks during prompt assembly; enforce zero-privilege operational model context | Load stored journal entry containing prompt injection payload into chat history and verify model treats content purely as data | Bounded residual risk of non-standard model response mitigated by output allowlist rendering and degradation protocols |
| Zone 2: Planning and reasoning | Gemini system instruction boundary | User input attempting to alter model persona or system directives via control sequence injection | Bypass of tone, scope, or behavioral boundaries set in system instruction | Enforce static system instructions via API configuration parameters separate from dynamic user content payloads | Send system directive bypass strings in user prompt and verify model output adheres strictly to baseline persona | Bounded residual risk of subtle instruction drift managed by token limits and automated evaluation degradation |
| Zone 2: Planning and reasoning | Multi-turn history context payload | History payload injection attempting to trigger operational tool execution or grant administrative context | Attempted tool execution or privilege escalation via dialogue manipulation | Enforce architecture rule where multi-turn history and model outputs can never grant privilege or trigger backend tool authority | Inject tool execution syntax into dynamic chat history and verify server executes no downstream tools or functions | Bounded residual risk of unhelpful response generation managed by strict operational model boundary enforcement |
| Zone 2: Planning and reasoning | Model feature context configuration | Attacker attempts to trigger grounding, web search, code execution, or media processing via input payload manipulation | Data exfiltration, dynamic code execution, or unintended external network activity from model environment | Explicitly disable grounding, web search, media processing, prompt caching, and dynamic code execution on all API generation configurations | Send prompt requesting code execution or web browsing and verify API returns plain text without executing code or web requests | Bounded residual risk of standard text response hallucination bounded by strict output sanitization and UI isolation |
| Zone 3: Tool execution | Server-side Gemini API authentication | Theft or exposure of Gemini API key through source code leakage, environment dump, or binary inspection | Unauthorized use of Gemini API key, quota exhaustion, and service account compromise | Store Gemini API key in Google Cloud Secret Manager; grant runtime identity secret accessor role; ensure Cloud Run receives GEMINI_API_KEY only through approved Secret Manager runtime injection | Scan source code repository, client bundle, build output, logs, and server responses to verify complete absence of hardcoded API keys without claiming the approved injected runtime value is absent | Bounded residual risk of secret version leak mitigated by immediate secret key rotation and access credential revocation |
| Zone 3: Tool execution | Arbitrary tool execution and model tool routing mechanism | Malicious user prompt or manipulated model output attempts to invoke unapproved backend tools, execute system commands, or escalate privileges | Unauthorized system command execution, remote code execution, or privilege escalation | Enforce server routes and available tool sets as immutable allowlisted operations; strictly block user content and model output from selecting tools, executing dynamic commands, or gaining backend privileges | Submit injection payloads requesting tool calls, shell execution, or unmapped endpoints and verify system rejects unmapped tools and executes zero commands | Bounded residual risk of unexpected text generation constrained by immutable route allowlists and zero-tool architecture |
| Zone 3: Tool execution | Gemini API availability and error status handling | Primary Gemini model experiences 503 UNAVAILABLE, 429 RESOURCE_EXHAUSTED, 404 NOT_FOUND, or 500 INTERNAL errors | API call failures leading to application downtime or unhandled server crashes | Execute model fallback ladder in exact order gemini-3.6-flash then gemini-3.1-flash-lite then gemini-flash-latest then gemini-3.7-flash; every attempt reserves/consumes durable global monthly capacity before issue; advance sequentially only on 503, 429, 404, or 500 errors; all other status codes and exhausted ladder return safe error without generic retry | Simulate HTTP 503, 429, 404, and 500 status codes to verify ladder progression, and simulate a non-listed status code to verify immediate safe error return without fallback or retry | Bounded residual risk of ladder exhaustion resulting in graceful HTTP 503 service unavailable error to client |
| Zone 3: Tool execution | Gemini API model tier usage and resource cost boundary | Model execution upgrading to paid tiers or infrastructure expanding beyond defined bounds | Unexpected billing charges, cost overruns, or operational tier violation | Explicitly prohibit Gemini paid tiers, prepay, auto-reload, Search/Maps grounding, media/file generation, prompt caching, dynamic code execution, VPC connectors, GPUs, PITR/backups/TTL, log exports, Cloud Trace, paid custom metrics, and additional databases; enforce default single Firestore database, one active Secret Manager secret version, and zero VPC usage | Audit deployment configuration and project parameters to confirm absence of paid tier triggers, grounding tools, VPC connectors, backups, trace/export services, or extra DBs | Bounded residual risk of capacity limit rejection bounded by rate limiting and accessible user feedback |
| Zone 3: Tool execution | Prompt and output token cap enforcement | Large input payloads or unconstrained output generation consuming excessive quota and memory | Exhaustion of API quotas, slow response latency, and buffer allocation failures | Enforce strict token limits (never character limits): chat prompt input capped at 1000 tokens / chat response output capped at 300 tokens; summary prompt input capped at 300 tokens / summary output capped at 100 tokens; count tokens and reject or trim requests before calling API | Submit chat prompt exceeding 1000 input tokens and verify request is rejected or trimmed prior to Gemini API call | Bounded residual risk of near-limit requests bounded by strict token validation and early middleware termination |
| Zone 3: Tool execution | Firebase Admin SDK execution privileges | Backend Cloud Run runtime identity holds excessive permissions (e.g. Owner or Editor) across cloud project | Compromise of Cloud Run container allowing complete project resource takeover | Assign dedicated runtime identity with minimal roles: Secret Manager Secret Accessor on named secret, narrow Firestore access, and App Check verifier | Audit GCP IAM permissions for runtime service account and verify absence of Owner, Editor, or broad administrative roles | Bounded residual risk of compromised runtime limited to narrow Firestore path access and rapid identity token revocation |
| Zone 4: Memory and state | Storage of user journal documents in Firestore | User A attempts to list, read, write, or delete journal documents belonging to User B | Data breach, horizontal privilege escalation, and loss of user privacy | Structure documents at path users/{verifiedUid}/interactions/{interactionId}; enforce owner-bound Firestore Security Rules checking request.auth.uid == userId | Execute test suite performing list, read, write, and delete operations as User A against User B paths and confirm 100% rejection | Bounded residual risk of backend Firebase Admin bypass mitigated by deriving all Admin paths exclusively from verified token UID |
| Zone 4: Memory and state | Firestore Admin SDK access path generation | Server code handles document paths using unvalidated client inputs during Admin SDK calls | Rules bypass via Admin SDK leading to accidental cross-user data access | Derive all Firestore document paths strictly from verified JWT UID parameter in server logic; never trust client-provided path strings | Send request with valid User A token requesting User B interactionId; verify backend writes only to User A document namespace | Bounded residual risk of code path flaw mitigated by unit test verification of path generator functions |
| Zone 4: Memory and state | Document state lifecycle tracking and schema completion | Server crash or network disruption during generation leaves database state inconsistent or user work lost | Data loss, orphaned pending operations, and UI state locking | Persist input and generated output with explicit status states pending, failed, or completed; write completed record containing user input, assistant output, automatic summary, session ID, turn order, model used, timestamps, status, and idempotency request ID under owner path users/{verifiedUid}/interactions/{interactionId} | Simulate failure mid-generation and verify document state reflects failed, draft remains in UI, and Retry Save is available | Bounded residual risk of unconfirmed pending writes resolved by status cleanup on subsequent request initialization |
| Zone 4: Memory and state | Storage payload cleanup before Firestore SDK call | JavaScript undefined values passed into Firestore setDoc or updateDoc SDK calls causing runtime crashes | Application crash during database write operations causing generation failure | Apply strict undefined-stripping utility to payload objects prior to database write operations | Pass object containing undefined values to database persistence layer and verify successful document write without exception | Bounded residual risk of missing optional fields handled by explicit default schema value assignments |
| Zone 4: Memory and state | State idempotency across server restarts | Client resends request due to network drop causing duplicate generation or repeated interactions | Duplicate resource creation, unnecessary quota consumption, and state corruption | Implement durable Firestore idempotency tracking interactionId state across restarts; return existing state on retry | Send identical interactionId twice and verify second call returns cached status without re-executing Gemini model | Bounded residual risk of concurrent request race condition handled by Firestore transactional state lock |
| Zone 4: Memory and state | Interaction volume and rate limit control | Abusive user or bot exhausts API quota through rapid automated interaction submissions | Denial of service, model quota exhaustion, and resource starvation for other users | Enforce a durable global service-wide maximum of 10 completed interaction units per calendar month plus one user-initiated interaction per minute per verified UID; reserve and charge durable global monthly capacity before every model attempt, including chat, each permitted fallback, and the synchronous summary, while allowing all attempts belonging to one admitted interaction to proceed; fail closed accessibly with clear UI error feedback | Test the global 11th monthly interaction unit; a second user submission within one minute for the same UID; fallback-attempt capacity exhaustion; and that one permitted fallback plus the synchronous summary can execute within one admitted interaction | Bounded residual risk of transient rate-limit lockout bounded by automated window resets and clear capacity feedback |
| Zone 4: Memory and state | Synchronous inline interaction summary generation | Inline summary generation process triggering secondary queues, workers, or untrusted background tasks | Execution overhead, state tracking complexity, and unauthorized trigger execution | Generate exactly one automatic inline summary capped at 100 output tokens synchronously for each completed interaction without background queues; write complete interaction record under owner path | Submit valid journal interaction and verify single inline summary (max 100 tokens) is produced and saved directly within primary request flow | Bounded residual risk of slight latency increase bounded by 100-token summary output cap |
| Zone 4: Memory and state | Client-side draft retention and persistence | Unsaved user journal entries lost on network failure or lost connection | User frustration and loss of unpersisted journal reflections | Retain draft text in client memory; display accessible Retry Save option on failure; clear draft only upon confirmed write | Intercept network during save, verify draft remains in editor input buffer, and verify Retry Save successfully completes write | Bounded residual risk of browser tab closure before save mitigated by explicit user confirmation prompt |
| Zone 5: Inter-system communication | Browser to server authentication flow over HTTPS | Unauthenticated browser clients attempt direct password manipulation, forged headers, or cross-user token reuse to access protected API endpoints | Unauthorized endpoint access, identity theft, or cross-user data leakage | Implement browser authentication using Firebase Google Sign-In only with zero password collection; transmit browser bearer Firebase ID token and App Check token over HTTPS; server verifies both tokens before granting access to protected or model routes | Perform authentications using missing tokens, invalid tokens, and cross-user token substitutions over HTTPS and verify backend rejects all unauthenticated or cross-user access attempts with HTTP 401 | Bounded residual risk of authentication identity provider latency managed by Firebase Auth client caching and rate limiting |
| Zone 5: Inter-system communication | Cloud Run to Gemini Developer API traffic and runtime configuration | Network interception, credential exposure, or resource over-provisioning on Cloud Run egress | API key exposure, payload inspection in transit, or infrastructure cost expansion | Deploy Cloud Run in asia-south1, min 0 / max 1 instance, 1 vCPU / 512MiB RAM, concurrency 4, 15-second timeout; enforce no VPC connector, Private Google Access, Flow Logs, Cloud Trace, or log exports; use HTTPS/TLS flow for Gemini Developer API traffic | Inspect deployment configuration flags and execute HTTP smoke test against backend endpoint | Bounded residual risk of TLS authority compromise mitigated by Google-managed certificate validation and rotation |
| Zone 5: Inter-system communication | Cloud Run to Firestore communication and infrastructure parameters | Database traffic interception or unconstrained network telemetry on Cloud Run database egress | Database credential theft, payload tampering, or operational log cost leakage | Enforce Google-managed HTTPS/TLS flow using SDK authentication; maintain Cloud Run limits (asia-south1, min 0 / max 1, 1 vCPU / 512MiB RAM, concurrency 4, 15-second timeout) with no VPC connector, Private Google Access, Flow Logs, Cloud Trace, or log exports | Inspect deployment configuration flags and run end-to-end database write smoke test | Bounded residual risk of cloud infrastructure transport failure mitigated by SDK automatic connection retry |
| Zone 5: Inter-system communication | Secret Manager access binding and Cloud Run deployment configuration | Cloud Run application runtime retrieving secrets during initialization or deployment | Secret leak via ambient environment variables, broad permissions, or excessive egress tooling | Bind Cloud Run container directly to single named Secret Manager secret version via IAM runtime identity over HTTPS/TLS; state no VPC connector, Private Google Access, Flow Logs, Cloud Trace, or log exports; ensure Cloud Run receives GEMINI_API_KEY only through approved Secret Manager runtime injection | Inspect deployment configuration files, client bundle, build outputs, logs, responses, and IAM policy bindings to confirm direct dynamic secret binding without VPC connectors and without claiming the approved injected runtime value is absent | Bounded residual risk of unauthorized IAM access prevented by strict least-privilege IAM policy bindings |
| Zone 5: Inter-system communication | UI Output rendering of journal entries and summaries | Reflected Cross-Site Scripting (XSS) via injected HTML/JavaScript inside model responses or journal text | Session hijacking, client-side script execution, and unauthorized DOM manipulation | Render dynamic model output and journal entries using plain-text or strict allowlisted Markdown rendering without raw HTML | Inject script alert tags into prompt and model response; verify rendered UI displays literal text without script execution | Bounded residual risk of Markdown parser edge cases mitigated by strict element allowlisting and zero HTML raw rendering |
| Zone 5: Inter-system communication | Server error responses and operational logging | Operational logs or client error payloads exposing API keys, ID tokens, or raw user journal text | Sensitive data leak to logging infrastructure or client error interfaces | Sanitize all error responses and logs; verify logs never contain journal text, Firebase/App Check tokens, prompts, or API keys; state no log exports or Cloud Trace | Trigger server error conditions and inspect stdout/stderr logs and client responses to confirm complete absence of sensitive data | Bounded residual risk of unhandled exception system traces prevented by top-level catch-all error handling middleware |
